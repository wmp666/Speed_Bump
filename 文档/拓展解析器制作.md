# 了解什么是开发版本
## 为什么有开发版本
> 开发版本是为了方便开发者可以快速判断新的减速带版本究竟是否需要同步更新拓展
- 因开发版本的更改仅会发生在修改与拓展加载有关的更新时更改
## 如何判断开发版本
> 正确判断开发版本有助于你节约不必要的开发时间
- 判断开发版本首先需要知道其构成
    - a.b
    - a: 意味着整个拓展功能完全重置,或者说意味着这个版本对原来的版本完全不兼容,需要开发者重新做一遍拓展
    - b: 当前版本是在上一个版本的基础上进行了功能新增——增加了新内容,这些内容建议开发者进行同步更新

# 制作
1. 新建项目时，将DownLoader作为项目库
2. 编写一份info.json(根目录)
   1. id：在其中写一个不会与其他解析器冲突的ID(id)，请确保这个ID与Parse.getID()中的值一致
   2. plugin_support_version_start, plugin_support_version_last：当前开发时的减速带开发版本(plugin_support_version_start -> plugin_support_version_last)
   3. version：拓展版本
   4. author：作者
   5. mainClass：你的解析器的完整位置
       - 例子：如 com > wmp > demo > DemoParser 写成："mainClass": "com.wmp.demo.DemoParser"
   6. support_platform: 推荐的使用平台(all/mac/windows/linux),不输入表示为全平台,该数据仅用于安装警告
3. (可选)编写介绍——introduction.md(根目录), 受限于原生JEditorPane, 对Markdown支持率较低
4. 解析器必须继承于AbstractParser，随后按照减速带中Parser编写方法编写

## 提示
- LinkInfoPanel数据传递到Task需要使用jsonInfo记入需要传输的数据，在Task中通过jsonObject获取
- 减速带当前的开发版本需要在拓展的开发版本之间(plugin_support_version_start < plugin_support_version(减速带) < plugin_support_version_last)
- 开发版本中使用 + 表示取不尽，
  - (1.0.0, +) -> [1.0.0, +∞)
  - (+, 3.0.0) -> (-∞, 3.0.0]
