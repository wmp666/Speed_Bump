# 「应用商店」纯 jar 拓展实现方案（不改主程序）

> 目标：不修改下载器（减速带）主程序源码，只通过一个自制 jar **解析器拓展**，
> 在应用内新增一个「应用商店」标签页：浏览/搜索软件、点击后复用现有下载管线把安装包下回来。
> 当前文档仅列完整实现设计，不落盘可运行工程。

---

## 0. 可行性判定（先看结论）

| 诉求                            | 判定               | 说明                                                                                                           |
| ----------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------ |
| 不改主程序、纯 jar 实现商店 UI           | ⚠️ 可行但属"越权 hack" | 靠 `Downloader.mainFrame`/`mainTabbedPane` 两个 `public` 字段 + 插件构造函数副作用注入。**能跑**，但依赖主程序内部字段和启动时序，主程序作者改了布局就会失效。 |
| 在插件"构造函数里添加商店标签页"             | ✅ 可行             | 插件无参构造在 `Downloader()` 构造期间被调用，此时 `Downloader.mainFrame != null`。见 §3。                                       |
| 使用火绒 / 华军 / 软件园作软件源           | ❌ 基本不可行          | 无公开稳定 API，见 §6。                                                                                              |
| 用官方发布渠道 / winget / scoop 作软件源 | ✅ 可行             | 见 §6 与 §7 的适配器设计。                                                                                            |
| 复用现有下载任务管线                    | ✅ 可行             | 用 `ParserTaskInfo.getParser(url)` + `getLinkedInfoPanel().getJsonInfo()`，见 §9。                               |

**一句话**：能做，且体验接近真商店；但本质是"借壳注入"，不是官方插槽。若想长期稳定，应推动主程序作者提供正式的"插件启动回调 + 可插入标签页"扩展点（见 §12）。

## 1. 现有拓展机制的解剖（必须理解的源码事实）

- 拓展 = 一个 **`AbstractParser` 的 jar 插件**，放在 `ParsersATools` 目录。
- `ParserTaskInfo` 的静态块 `static { loadParsers(); }` 在首次用到该类时执行：
  `ParserTaskInfo.java:46`。
- `loadParsers()` 扫描目录下每个 jar：
  1. 读 jar 根目录 `info.json`（id / 版本区间 / author / mainClass / support_platform），`getParserInfoFromJar`。
  2. 用 `URLClassLoader`（父加载器=系统类加载器，能访问主程序类）加载，见 `loadParserFromJar`。
  3. `Class.forName(mainClass, true, classLoader).getDeclaredConstructor().newInstance()` —— **在此实例化你的插件**，`ParserTaskInfo.java:289-290`。
- 所以**插件类被 `new` 出来，本身没有任何"启动回调"**；用户想用的"构造函数副作用"，就是把 `new` 当作唯一的、会稳定执行的入口。
- 主程序窗口对象：
  - `public static Downloader mainFrame;` —— `Downloader.java:41`
  - `public static Downloader mainFrame = this;` —— 在构造器首行赋值，`Downloader.java:114`
  - `public JTabbedPane mainTabbedPane;` —— `Downloader.java:49`，是真正的主 UI 标签容器。
- 现有「拓展页」`PluginParserPanel`（含"可安装列表"）本身也是主程序内置的，不是一个 jar 插件页面。作者已用 GitHub Release 作为插件分发源，见 `getInstallPluginParserInfoList`。

## 2. 架构总览

```
plugin-jar（你的拓展，compile-only 依赖 DownLoader）
│
├── info.json            ← 插件元数据（给框架加载用）
├── introduction.md      ← 可选，拓展页介绍
│
└── 你的包
    ├── AppStoreBootParser extends AbstractParser   ← 对外必须是一个合法解析器
    ├── AppStorePanel / ...                        ← 商店 UI（注入到 mainTabbedPane 的 JPanel）
    ├── store/
    │   ├── StoreEntry        ← 软件条目（模型 + JSON 序列化）
    │   ├── Source            ← 软件源接口
    │   ├── LocalJsonSource   ← 本地/远程 JSON 清单源（默认）
    │   ├── OfficialSource    ← 官方直链清单源（可加）
    │   └── WingetManifestReader（可选进阶）
    ├── service/
    │   └── DownloadHelper    ← 复用主程序下载管线（§9）
    └── ui/SettingsPanelStore ← AbstractSpecialSettingsPage，顺带提供设置页
```

职责切分：

- **`AppStoreBootParser`** 负责"被框架加载"这个唯一入口，并在构造时（幂等地）把商店标签页注入主窗口。
- **商店 UI** 是纯 Swing（FlatLaf 风格），搜索 → 展示软件卡片 → 点下载 → `DownloadHelper`。
- **软件源**是可插拔的 `Source` 实现，UI 不关心来源。

## 3. 注入标签页的完整机制

### 3.1 时序推理

- `ParserTaskInfo.loadParsers()` 在**首次主动使用 `ParserTaskInfo` 类**时触发（静态块）。
- 主程序 `Run.main` → `new Downloader()`（`Run.java:85`）→ `Downloader()` 构造器第一行 `mainFrame = this`。
- 只要"首次触发 `ParserTaskInfo`"发生在 `Downloader` 构造体内（构造函数调用 `initTaskComponents()` 等会访问 `ParserTaskInfo`，例如菜单里 `ParserTaskInfo.getEnablePluginParserList()`，`Downloader.java:776`），那么你的插件构造被调用时 `Downloader.mainFrame` 已就绪。
- 但 `mainTabbedPane` 内的组件此时可能仍在组装中 → **不要把 addTab 直接写在构造器里同步执行**，用 §3.3 的延迟挂载。

### 3.2 一个前提（类加载方向）

插件以 DownLoader 作为库，但**不要把任何主程序类打进你的 jar**。必须用 `compileOnly`/`provided` 依赖，保证 `Downloader`、`ParserTaskInfo`、`HTTPParser` 等由**父加载器**解析，插件 jar 里只有你自己的类和第三方小库。否则会出现两个 `Downloader` 类副本、`instanceof` 失败、甚至 `mainFrame` 指向错误类。

### 3.3 幂等 + 延迟挂载引导器

插件类可能被实例化多次（启动一次、用户点"刷新/更新"再 `loadParsers()`）。每次 `new` 都会跑构造函数 → 必须幂等。

```java
public final class StoreInstaller {
    private static final AtomicBoolean DONE = new AtomicBoolean(false);

    /** 只允许注入一次商店标签页。 */
    public static void ensureInstalled() {
        if (DONE.compareAndSet(false, true)) {
            SwingUtilities.invokeLater(StoreInstaller::doInstall);
        }
    }

    private static void doInstall() {
        // 主窗口可能还没构造完，轮询等待 mainFrame 与 mainTabbedPane 就绪
        Downloader d = Downloader.mainFrame;
        if (d == null || d.mainTabbedPane == null) {
            Timer retry = new Timer(100, e -> doInstall());   // 简单自旋；正式版建议上限次数
            retry.setRepeats(false);
            retry.start();
            return;
        }
        if (hasTab(d, "应用商店")) return;          // 二次防御，见下
        var panel = new AppStorePanel();
        d.mainTabbedPane.addTab("应用商店", panel);
        // 若想让点击聚焦到此页：
        // d.mainTabbedPane.setSelectedComponent(panel);
    }

    private static boolean hasTab(Downloader d, String title) {
        for (int i = 0; i < d.mainTabbedPane.getTabCount(); i++) {
            if (title.equals(d.mainTabbedPane.getTitleAt(i))) return true;
        }
        return false;
    }
}
```

> 用 `invokeLater` 是因为：刷新场景下 `loadParsers()` 不一定在 EDT 上执行；把 UI 变更丢到 EDT 队列里最安全。主窗口通常在构造后几百 ms 内显示，轮询即可。
> 若主程序作者后续给 `Downloader` 加图标注册（`IconControl.addInDynamicConverter` 只处理内置几个页的图标，`Downloader.java:145-154`），新增 tab 无图标 → 可自己 `putClientProperty` 或调 `mainTabbedPane.setIconAt` 设置。

## 4. 对外插件壳（必须同时是一个"合法解析器"）

即使你的真实目的是注入页面，框架仍要求 `mainClass` 指向一个 `AbstractParser` 子类，且能被无参 `new`。最简单的做法：让它同时成为一个低门槛解析器（例如识别 `store://查询词` 之类输入，给出搜索结果），这样它在"拓展页/解析器列表"里是合法的，不会因 `isMeetRequirements` 永远 false 而被当成坏插件——虽然并非必须。

```java
public class AppStoreBootParser extends AbstractParser {
    public AppStoreBootParser() {
        // 关键副作用：注入商店页（幂等、延迟）
        StoreInstaller.ensureInstalled();
    }

    @Override public String getID() { return "app-store"; }
    @Override public String getSupportTip() { return "应用商店 · AppStore"; }

    @Override protected void updateLinkInfo(String link) { /* 记录/解析，可空 */ }

    @Override public boolean isMeetRequirements(String link) {
        return link.strip().toLowerCase().startsWith("store://");
    }

    @Override protected AbstractLinkInfoPanel getLinkedInfoPanel(String link, Info info) {
        // 可选：store://微信  → 弹一个"开始搜索"面板；直接返回 null 也不会崩（框架有兜底，见 ParserTaskInfo 兼容分支）
        return null;
    }

    @Override protected AbstractTask getTask(String link, JSONObject infoJson) { return null; }

    @Override public AbstractSpecialSettingsPage getSettingsPage() {
        return new AppStoreSettingsPage();  // 顺带塞一个"商店设置"，见 §8
    }
}
```

> 关键点：**构造里注入**，其余解析器方法可尽量空实现。`getSettingsPage()` 能返回你自己的设置面板（会被放到"专项设置"里），这是又一个免费的 UI 出口。

## 5. 商店 UI 设计（纯 Swing + FlatLaf）

因为 `mainTabbedPane` 里的页面各自是 `JPanel`，你的商店就是一个 `JPanel`，自包含：

- 顶部：搜索框（`JTextField`）+ 分类下拉 + 刷新按钮。
- 中部：软件列表（用 `JTable` 或自绘 `JList` CellRenderer，参考 `PluginParserPanel` 里 `setCellRenderer` 手绘选中背景的风格 `PluginParserPanel.java:98-149`）。
- 每行：软件名、作者/来源、版本、平台标签、右侧「下载」按钮。
- 点下载：调 `DownloadHelper.download(entry)`（§9）。

骨架（示意，不必现在写全）：

```java
public class AppStorePanel extends JPanel {
    private final JList<StoreEntry> list = new JList<>();
    private final DefaultListModel<StoreEntry> model = new DefaultListModel<>();
    private final List<Source> sources = List.of(new LocalJsonSource(DataControl.getDataPath()));

    public AppStorePanel() {
        super(new BorderLayout(8, 8));
        setOpaque(false);
        // 顶部工具栏……
        // 列表 + CellRenderer（软件名粗体、副行来源/版本/平台）……
        list.addListSelectionListener(...);  // 点行展示详情
        // 「下载」按钮动作 → DownloadHelper.download(list.getSelectedValue());
    }
}
```

窗口标题文本走 `StringFormat.translate`（看主程序语言机制，可用 `StringFormat.translate("task", "...")` 风格），不必强做多语言，先写死中文亦可。

## 6. 软件源调研结论（重要：别踩坑）

| 你提到的源                              | 现实                                                                                                                                                                                                                                     | 结论                       |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 火绒（应用商店/下载频道）                      | 火绒**不是应用商店**；官方论坛明确表示没有面向第三方的应用/软件下载公开 API。参见 [火绒社区](https://bbs.huorong.cn/forum.php?mod=viewthread&tid=109971)。                                                                                                                      | ❌ 无法作为"商店源"。             |
| 华军 / 软件园 / 太平洋等聚合下载站               | 无公开稳定 API；直链多为运行时拼接、带跳转/反爬；镜像包常捆绑推广；页面属于站点商业数据。按 [《反不正当竞争法》2025 修订](https://www.kingandwood.com/cn/zh/insights/latest-thinking/key-takeaways-of-the-2025-revision-of-china-s-anti-unfair-competition-law.html) 精神，未经授权大规模抓取并重新分发有合规风险。 | ❌ 不建议作为数据源。              |
| **官方发布渠道**（各软件官网/ GitHub Releases） | 稳定、正版、无捆绑。                                                                                                                                                                                                                             | ✅ 推荐。                    |
| **包管理清单**（winget / scoop / choco）  | 结构化元数据（winget-pkgs manifest 开源，见 [microsoft/winget-cli 包管理文档](https://deepwiki.com/microsoft/winget-cli/3-package-management)）。**元数据可用，但下载 URL 仍是官方直链**。                                                                               | ✅ 可作为"软件清单/搜索来源"，直链仍走官方。 |

**推荐策略**：以"自己维护的 JSON 清单"为核心源（软件名 → 分类 → 官网直链 → 版本 → 校验和），少量手工条目起步；可选地定时拉 winget-pkgs 的 manifest 扩充条目，但**永远下载官方直链**。不要对华军/软件园等做页面对抗式爬取。

## 7. 数据模型与软件源接口

```java
// 一个软件条目（含具体某版本的下载信息）
public class StoreEntry {
    public String id;            // 全局唯一
    public String name;          // 显示名，如 "微信"
    public String category;      // "社交"
    public String vendor;        // "腾讯"
    public String version;
    public String description;
    public String homepage;
    public String downloadUrl;   // 官方直链
    public long sizeBytes;
    public String sha256;        // 可选：安全校验
    public String platform;      // windows / all
    public boolean bundleRisk;   // 是否"安装包"，仅展示提示用
}

// 软件源：UI 只依赖它
public interface Source {
    List<StoreEntry> list(String keyword, String category); // 搜索
    StoreEntry latest(String id);                            // 查最新
}
```

本地/远程清单 JSON 例子（`store-catalog.json`，可放在 `DataControl.getDataPath()` 下让用户可编辑，或随插件附带）：

```json
{
  "schema": 1,
  "updated": "2025-01-01",
  "entries": [
    {
      "id": "wechat.win",
      "name": "微信",
      "category": "社交",
      "vendor": "腾讯",
      "version": "3.9.12.17",
      "homepage": "https://pc.weixin.qq.com/",
      "downloadUrl": "https://dldir1.qq.com/weixin/Windows/WeChatSetup.exe",
      "sha256": "……",
      "platform": "windows"
    }
  ]
}
```

> `downloadUrl` 务必是**官方发布直链**，且建议条目带 sha256。商店下载后可选校验，降低被投毒风险（本下载器是通用下载器，不负责安装/签名验证——这点要在 UI 明示：下载≠安装，是否运行由用户决定）。

## 9. 复用下载管线（关键：不要手拼 jsonInfo）

商店点「下载」时，最省心、最不易出 bug 的方式是走官方 HTTP 解析器流程，让框架自己生成 `jsonInfo`：

```java
public final class DownloadHelper {
    public static void download(StoreEntry e) {
        Downloader d = Downloader.mainFrame;
        if (d == null) return;
        try {
            // 1) 交给 HTTP 解析器（isMeetRequirements 要求以 http 开头 → 命中 HTTPParser）
            AbstractParser parser = ParserTaskInfo.getParser(e.downloadUrl);
            if (parser == null) { ToastMessage.show("不支持的下载链接", ToastMessage.ERROR); return; }

            // 2) 框架生成 Info / 信息面板，里面带齐 jsonInfo 键
            AbstractParser.Info info = parser.getInfo(e.downloadUrl);
            AbstractLinkInfoPanel panel = info.getLinkedInfoPanel();
            JSONObject jsonInfo = panel.getJsonInfo();   // 键由框架填好（savePath 等在下一步覆盖）

            // 3) 覆盖/补齐用户关心的字段（与 PluginParserPanel.java:217-220 一致）
            jsonInfo.put("savePath", DataControl.get("DownloadPath", ""));
            jsonInfo.put("threadMode", 0);
            jsonInfo.put("threadNum", DataControl.get("ThreadNum", 64));
            jsonInfo.put("linkStyle", 0);

            // 4) 生成任务并加入下载器（EDT）
            AbstractTask task = info.getTask(jsonInfo);
            SwingUtilities.invokeLater(() -> d.addDownloadTask(task));
        } catch (Exception ex) {
            // log4j
        }
    }
}
```

> 参照主程序「拓展页」安装按钮的做法（`PluginParserPanel.java:204-223`），证明这套调用是作者自己也在用的"从 URL 建任务"标准姿势。
> 若以后希望"下完自动做某事"（如弹完成通知），可仿照 `PluginParserGithubDownloadTask` 包一层 `HTTPDownloadTask` 并覆写 `runWhenFinally()`。

## 10. 打包插件 jar（info.json 规范）

`info.json`（jar 根目录，规范见 `拓展解析器制作.md`）：

```json
{
  "id": "app-store",
  "mainClass": "com.yourplugin.AppStoreBootParser",
  "plugin_support_version_start": "1.0.0",
  "plugin_support_version_last": "+",
  "version": "0.1.0",
  "author": "你",
  "support_platform": "all"
}
```

- `plugin_support_version` 取作者当前开发版本 `Run.PLUGIN_SUPPORT_VERSION = 1.1.2`（`Run.java:23`）所在区间，例如写 `"1.1.0"~"+"`；写错会弹版本不符警告。
- `mainClass` 必须指向 `AbstractParser` 子类、有**无参构造**。
- 需要框架的"拓展页可安装列表"里出现你的插件：按 `installPlugin.md` 的格式发布到 GitHub Release 的 Body（`### 信息` + `### 介绍`），并在 Release 挂一个 `.jar` asset（见 `parsePluginInfoFromBody` 的解析规则）。
- 记得 jar 里**排除主程序类和其依赖**（仅保留你写的类 + 额外小库），否则类冲突。

## 11. 明确的风险与坑清单

1. **无官方插槽，属越权用法**：`mainFrame`/`mainTabbedPane` 是 public 字段但不是给插件用的正式 API；主程序改版可能重命名/重排布局 → 注入失效。开发版本号 `a.b` 中 `a` 变更是"完全不兼容"信号（`拓展解析器制作.md`）。
2. **EDT**：不要在插件构造函数里直接改 UI；一律 `SwingUtilities.invokeLater`。
3. **幂等**：`loadParsers()` 会被反复调用（启动 + 刷新 + 更新），必须用静态标志 + 查重防止重复 tab。
4. **类加载器**：插件依赖主程序类必须走父加载器，禁止把主程序类打进 jar。
5. **ClassNotFound / 版本区间**：`getSettingsPage`、解析器方法里用到的任何主程序 API 都要确认在当前开发版本存在。
6. **软件源合规**：只走官方直链；勿对抗式抓取聚合站商业数据（见 §6 法规引用）。
7. **安全边界**：本下载器不负责软件签名/杀毒校验。UI 需注明"来源以官方清单为准，下载后自行校验/杀毒"。
8. **多 tab 与窗口重建**：若主程序将来支持"重建/重建 UI"，你的注入逻辑要能对应地重建或至少不抛异常。

## 12. 更稳妥的长期方向（建议反馈给主程序作者）

若想让"应用商店"成为一等公民且长期稳定，最干净的做法是请主程序作者（也是你，如果你就是作者/可维护主程序）提供：

- 一个**插件启动回调**（例如在 `Downloader` 构造末尾遍历 `getEnablePluginParserList()`，若解析器实现了 `AppPluginLifecycle` 接口则调用 `onAppReady(Downloader)`）；
- 一个**插件可插入的标签页扩展点**（例如公开 `mainTabbedPane.addPluginTab(title, component)` 的正式方法，并纳入图标/主题管理）。

这样商店插件就不再依赖"构造函数副作用"，加载时机与生命周期都由主程序保证，刷新/卸载也更干净。

> 注：本项目的"拓展"本是"解析器"，面向"把某种输入变成下载任务"。商店是**主动浏览型**页面，跟解析器的被动模型天然不同——这正是它需要新插槽的原因。
