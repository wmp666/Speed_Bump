减速带的下载与处理能力都统一挂在「解析器」体系下：HTTP、BT、Gopeed、Github 是内置解析器，其余能力以**拓展（插件）**形式装载。

## 一、什么是拓展

拓展就是**一个 jar 包**，其中包含若干继承 `AbstractParser` 的解析器。解析器负责把某种输入（链接或文件路径）解析成一张任务信息卡片，并据此创建下载 / 处理任务。

- 拓展目录：`~/.speed-bump/Data/ParsersATools/*.jar`
- 拓展页支持：查看**已安装**列表、启用 / 禁用、卸载（重启后完全生效）、导入本地 jar、刷新；以及从**拓展仓库的 Releases** 拉取可安装列表并一键安装 / 更新
- 内置的 Github 加速以「内置插件」形式出现，在列表中只读、不可卸载
- 拓展可以自带「专项设置」页（返回 `AbstractSpecialSettingsPage` 即可自动出现在专项设置中）

加载流程（`ParserTaskInfo.loadParsers()`）：

1. 扫描拓展目录下的每个 `.jar`
2. 读取 jar 根目录的 `info.json`（`id`、版本区间、`author`、`mainClass`、`support_platform`）
3. 用 `URLClassLoader`（父加载器为系统类加载器）加载 `mainClass` 并调用**无参构造**实例化
4. 按 `Parser.json` 中的禁用 / 删除列表决定是否启用；版本区间或平台不匹配时会弹出警告，由用户决定是否继续

> 因为插件是被直接 `new` 出来的、没有启动回调，所以**构造函数必须幂等**——`loadParsers()` 会在启动、刷新、安装拓展后被多次调用。

## 二、官方拓展

由拓展仓库 <https://github.com/wmp666/Speed_Bump_Plugin> 提供：

| 拓展 | 说明 |
| --- | --- |
| 哔哩哔哩链接解析器 | 支持大部分哔哩哔哩网页链接 / BV 号（视频、视频合集），不支持多线程下载 |
| 抖音分享链接解析器 | 解析抖音分享链接（视频、图集），依赖第三方 API，不支持多线程下载 |
| ED2K 解析器 | 解析 ED2K 链接，实际下载由 Gopeed 完成 |
| 图片格式转换器 | 读取 30+ 种图片格式，可写出 jpg / png / bmp / gif / tiff / ico / icns 等格式（把图片拖入链接框即可） |
| 每日金句 | 通过系统托盘通知，在启动时或每日固定时间点推送一句金句 |

## 三、写一个拓展

1. 新建项目，把本仓库作为项目库（**不要把主程序的类打进插件 jar**，主程序类必须由父类加载器解析）
2. 在项目**根目录**编写 `info.json`：

   ```json
   {
     "id": "我的解析器",
     "mainClass": "com.example.MyParser",
     "version": "1.0.0",
     "author": "你的名字",
     "plugin_support_version_start": "1.1.0",
     "plugin_support_version_last": "+",
     "support_platform": "all"
   }
   ```

3. （可选）根目录编写 `introduction.md` 作为拓展介绍（由原生 `JEditorPane` 渲染，Markdown 支持有限）
4. 解析器继承 `AbstractParser` 并实现以下方法：

   | 方法 | 作用 |
   | --- | --- |
   | `String getID()` | 解析器 ID，需与 `info.json` 的 `id` 一致 |
   | `String getSupportTip()` | 支持范围提示（创建任务窗口的「支持」按钮里展示） |
   | `boolean isMeetRequirements(String link)` | 判断该链接是否由本解析器处理 |
   | `AbstractLinkInfoPanel getLinkedInfoPanel(String link, Info info)` | 返回任务信息卡片 |
   | `AbstractTask getTask(String link, JSONObject infoJson)` | 依据 `infoJson` 创建任务 |
   | `void updateLinkInfo(String link)` | 在构造 `Info` 时触发，用于准备解析数据 |
   | `AbstractSpecialSettingsPage getSettingsPage()` | 专项设置页，没有则返回 `null` |

5. 面板与任务之间的数据通过 `AbstractLinkInfoPanel#getJsonInfo()` 产生的 `jsonInfo` 传递，任务侧再从构造参数 `jsonObject` 中取出（字段表见 [`src/json数据表.md`](../src/json数据表.md)）

### 开发版本号

- **开发版本**只在修改了与拓展加载相关的代码时变化：大版本（`a`）表示完全不兼容、需要重做拓展；小版本（`b`）表示新增功能、建议同步更新
- 拓展开发版本必须落在 `plugin_support_version_start ~ plugin_support_version_last` 区间内，`+` 表示无穷：`[1.0.0, +)` 写作 `"1.0.0"` ~ `"+"`
- `support_platform` 仅用于安装提示（`all` / `windows` / `linux` / `mac`，留空视为全平台）

## 四、发布与分发

拓展通过**拓展仓库的 GitHub Release** 分发：

- Release 的 **Tag 与标题使用拓展名**
- Release 的 Body 按以下格式书写，程序会解析其中的信息：

  ```markdown
  ### 信息
  name: 拓展名称
  author: 作者
  version: 1.0.0
  plugin_support_version: 1.1.0~+
  support_platform: all

  ### 介绍
  -> 从这一行开始是拓展介绍
  ```

- 在 Release 中挂上插件 jar 作为 asset（程序取第一个 asset 作为下载地址）

格式说明也可参见仓库根目录的 [`installPlugin.md`](../installPlugin.md)。

## 五、注意事项

- 主程序类必须由父类加载器解析：把主程序类打进插件 jar 会出现两个 `Downloader` 副本，导致类型判断失败
- 所用到的任何主程序 API，都要确认在当前拓展开发版本中存在
- 拓展安装列表来自网络（GitHub Releases），可用「专项设置 → Github 加速」加速
- 社区提交的「纯 jar 应用商店」设计方案（插件自己注入一个商店标签页）见 [`应用商店拓展实现方案.md`](../应用商店拓展实现方案.md)，该方案尚未并入主程序
- 更多入门说明见 [`拓展解析器制作.md`](../拓展解析器制作.md)
